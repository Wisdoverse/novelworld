# ADR NNNN: Decision title

- Status: Proposed
- Date: YYYY-MM-DD
- Owners: repository maintainers and affected component owners
- Related: issue or pull request link

## Context

Describe the user or operational problem, current constraints, evidence, and
the decision deadline. State what is out of scope.

## Decision

State the chosen behavior and the boundaries it changes. Include data
ownership, API compatibility, failure semantics, security/privacy impact, and
operational impact when applicable.

## Alternatives considered

List the viable alternatives and why they were rejected. Include retaining the
current design when that is a real option.

## Consequences

Record benefits, costs, new risks, migration requirements, observability, and
the conditions under which this decision should be revisited.

## Rollout and rollback

Define incremental rollout, compatibility window, success signals, abort
conditions, and the exact recovery path. If rollback is impossible, state why
and describe the forward-recovery plan.

## Evidence

Link the tests, measurements, threat-model updates, runbooks, or production
signals that validate the decision. Do not use this ADR itself as evidence.
